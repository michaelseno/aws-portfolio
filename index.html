CashFlow Tracker

Offline-first mobile app Product / personal finance UX

An offline-first personal finance app for everyday budgeting, cash visibility, and recurring money workflows that run locally on device.

Problem

Many budgeting tools feel cumbersome or too dependent on connectivity when the real need is quick, low-friction money tracking throughout the day.

Solution

A React Native workflow backed by local SQLite storage that keeps onboarding, dashboard views, recurring flows, savings tracking, transaction history, and account management usable without backend dependence.

Key highlights

  • Onboarding captures accounts, recurring income, bills, and savings goals before dashboard use.
  • Dashboard supports projected vs. actual spend, savings progress, quick actions, and transaction history.
  • Recurring bill, salary, savings, and account workflows stay local-first rather than cloud-dependent.
Current status: personal product framed around offline mobile execution today; the optional backend remains future-facing and is not required for the app experience. Public proof is limited in this phase, so walkthrough discussion is the safe follow-up path.

ReliabilityKit

MVP Reliability toolkit / Python + Playwright + pytest

A reliability toolkit that turns Python, Playwright, and pytest runs into structured diagnostics, artifacts, failure classifications, and trend-friendly reporting.

Problem

Flaky or failed test runs are expensive to triage when execution details are fragmented across logs, screenshots, and ad hoc reporting.

Solution

A local-first execution layer that captures structured run records and artifacts, classifies failures, computes reliability scoring, and surfaces trend analysis through a hosted dashboard proof path.

Key highlights

  • CLI-first execution with local run records and artifacts written to `.reliabilitykit/`.
  • Failure classification, reliability scoring, and dashboard-oriented trend analysis support faster debugging.
  • PR CI, scheduled CI, and dashboard workflows provide visible proof of active MVP evolution.
Current status: active MVP with local-first execution and AWS-hosted dashboard proof; the S3 persistence path is scaffolded rather than presented as fully finalized.

TestOrbit

Technical POC Cloud-native orchestration / frontend + backend proof

A self-serve test orchestration concept that combines a dashboard experience with serverless backend flows for suites, runs, scheduling, credits, and trigger-based execution.

Problem

Coordinating different test types and run triggers is difficult without a clear control plane, isolated execution model, and understandable operator workflow.

Solution

TestOrbit pairs a React frontend with a serverless orchestration backend so manual, scheduled, and webhook-triggered runs can move through suite management, credits, and execution flows as one product story.

Key highlights

  • Frontend includes the marketing site and authenticated dashboard for suites, runs, scheduling, credits, and webhook triggers.
  • Backend uses serverless control flows with AWS services and isolated runtime workers for execution handling.
  • Presented as one technical POC with separate frontend and backend proof links rather than two standalone portfolio entries.
Current status: technical POC with production-oriented patterns and public proof assets, but not framed as a launched SaaS product.

Approach

I optimize for usable interfaces, observable systems, and delivery choices that stay credible as a project matures.

Product clarity

  • Design around the main workflow before adding extra surface area
  • Keep UI states readable, responsive, and easy to scan
  • Favor explicit proof over vague portfolio claims

Execution discipline

  • Structure systems so runs, records, and artifacts are diagnosable
  • Separate control, execution, and reporting concerns where needed
  • Use the simplest architecture that still preserves maintainability

Cloud-aware delivery

  • Use AWS-hosted paths when they add clear proof or deployment value
  • Be explicit about POC vs. MVP vs. future-facing work
  • Keep handoff quality high with visible, source-controlled artifacts
